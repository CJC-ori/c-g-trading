# bot/backtest — deterministic backtest harness

Implements `SPEC.md` (the contract; read it first). Python 3.11, stdlib only.

## Layout

| file | what it is |
|---|---|
| `types.py` | frozen dataclasses: `Candle`, `Trade`, `MarketInfo`, `SettlementResult`, `OrderIntent`, `Fill`, `Position`, `Portfolio`, `MarketView`, `Strategy` protocol |
| `fills.py` | fill simulation as pure functions: taker crossing, maker vs trades, conservative OHLC rules, 25% volume caps, position/cash accounting, settlement payouts |
| `fees.py` | Kalshi fee model: taker `ceil_to_cent(0.07·P·(1−P))` per contract, category multiplier table, maker 0, fee-stress hook |
| `risk.py` | harness-enforced sizing: fee-aware fractional Kelly, per-market/event/total caps, depth cap, no-borrowing floor |
| `engine.py` | the replay loop: decision clock, point-in-time `MarketView`s, risk clamps, order lifecycle, settlements, inference cost, JSONL event log |
| `metrics.py` | SPEC §6 metrics + `report.json` / `report.md` writer, capacity-curve and fee-stress re-runs |
| `dataport.py` | `HistoryProvider` protocol, `InMemoryHistoryProvider` (tests), `SqliteHistoryProvider` (stub for bot/data) |
| `testkit.py` | builders + deterministic synthetic history for tests/smoke runs |

Reference strategies proving the loop live in `bot/strategies/baseline.py`
(`HoldFavorite`, `CoinFlip`).

## Run

```bash
# from repo root
python -m pytest bot/backtest/ -q          # full test suite

# smoke a baseline strategy on synthetic data and write a report
python - <<'PY'
from bot.backtest.metrics import full_report
from bot.backtest.testkit import synthetic_provider
from bot.strategies.baseline import HoldFavorite

report = full_report(
    synthetic_provider(seed=7),
    lambda: HoldFavorite(edge_cents=4),
    out_dir="runs/hold-favorite",
    label="hold-favorite-synthetic",
)
print(open("runs/hold-favorite/report.md").read())
PY
```

Against real data once `bot/data/` lands:

```python
from bot.backtest.dataport import SqliteHistoryProvider
provider = SqliteHistoryProvider("data/kalshi.db")
report = full_report(provider, lambda: MyStrategy(), out_dir="runs/my-strategy")
```

Full auditability: pass `EngineConfig(event_log_path="runs/x/events.jsonl")`
to get every decision/intent/clamp/order/fill/cancel/settlement as JSONL.

## Design notes

**Units.** Times are unix seconds; prices are integer cents in YES space
internally (1–99); money is integer cents. `OrderIntent`/`Fill` prices are in
the side's own space; `fills.normalize()` maps everything to a signed
yes-equivalent (buy NO at p ≡ sell YES exposure at 100−p), which makes NO-side
complementarity a structural property rather than a case to remember.

**No lookahead, structurally.** Strategies never see the provider. The engine
pre-slices each `MarketView` at decision time t: candles with `end_ts <= t`
(a candle ending exactly at t is fully past), trades with `ts < t`. The
decision clock is generated by the harness from the strategy's declared
cadence (`decision_interval_s`, `price_move_trigger_cents`), aligned to
candle boundaries — a strategy cannot be called between its own ticks.
`test_engine.py::TestNoLookahead` asserts the property against a provider
loaded with future data.

**Fills are pessimistic by construction.**
- A crossing intent (vs the bid/ask estimate at t) is a taker: it fills in
  the *following* candle window only, at the quote it crossed, capped at 25%
  of that window's printed volume. No fills at mid, ever.
- A passive order rests and fills only against subsequent trades at/through
  its limit (25% per print), or — when only candles exist — only if a candle
  goes *strictly* through the limit (a touch is not a fill), 25% of candle
  volume.
- `tif="ioc"` dies after the taker window; `tif="rest"` remainder rests until
  filled or market close. All resting orders are canceled at close.
- Quote estimate at t: latest candle's bid/ask close when available,
  otherwise last traded price ± 1c.
- When a market has both trades and candles, trades are the fill stream
  (candles would double-count the same tape); candles still drive the clock,
  quotes and marks.

**Accounting.** Positions are signed yes-equivalent qty + premium cost basis.
Reducing via the complement (e.g. buying NO against a YES long) is modeled as
the pair-redemption it is on Kalshi: net cash equals selling YES at the same
yes price. Voided markets refund exactly the cost basis. Partial-exit basis
release is floor-prorated so everything stays in integer cents. Selling a
side you don't hold is accepted and modeled as opening the complement
(exposure-identical; collateral folded into the premium convention).

**Sizing.** The risk layer clamps (never inflates) each intent: fee-aware
fractional Kelly from `p_hat` vs estimated fill price, then per-market (5%),
per-event (10%), total-deployment (80%) caps measured in premium at risk
(open basis + premium committed by resting orders), a hard cash floor
(no borrowing), and a 25% depth pre-clamp from recent candle volume.
Intents without `p_hat` can only reduce existing positions.

**Inference cost** is read from the strategy attribute
`last_inference_cost_cents` after every decision call and reported as its own
P&L line (gross and net). The equity curve is gross of inference.

**Metrics** (`full_report`): net P&L both ways, annualized on time-weighted
average deployed premium, Brier vs the market-mid baseline at the same
instants, calibration curve + ECE, max drawdown, top-5 concentration + worst
market, trade stats (fill rates vs intents, maker/taker mix, avg entry edge,
holding period), 60/40 time split and category split, capacity curve
(fresh runs at 1×/3×/10× depth multiplier), and fee stress (×1.5 re-run).
Reruns take a `strategy_factory` so state never leaks between runs.

## What remains to wire (once bot/data/ lands)

- `dataport.SqliteHistoryProvider`: written against the *assumed* schema
  (`markets` / `candlesticks` / `trades`, see `TODO(wire)` markers and the
  schema fixture in `test_dataport.py`). Validate table/column names, units
  (cents vs dollars, unix vs ISO times), and the settlement-result vocabulary
  against the real `data/kalshi.db`, then run the suite's sqlite tests over a
  real fixture.
- `fees.py TODO(verify)`: confirm per-category multipliers and the
  per-contract vs per-order ceil against Kalshi's official fee schedule
  (current implementation is the conservative upper bound).
- Bid/ask estimates assume bot/data stores candle-close bid/ask when Kalshi
  provides them; if absent the ±1c fallback stays (conservative-ish for
  liquid markets, optimistic for very wide books — revisit with real data).
- LLM-strategy contamination gate (only markets resolving after 2026-02-01)
  is a `market_filters`/provider concern; enforce at run configuration when
  wiring forecaster strategies.
